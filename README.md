## Project Overview

Given a reading passage, the system:

1. **Verifies answers** — takes an (article, question, option) triple and predicts whether the option is correct using binary classification
2. **Generates distractors** — extracts plausible but definitively wrong alternatives from the article using an ML ranker
3. **Generates hints** — surfaces article sentences in order of relevance to the question (least → most specific)
4. **Serves a 4-screen UI** — article input, quiz view, hint panel, and analytics dashboard

## Architecture

```
source.csv
    │
    ▼
create_splits.py ──────────────────► train.csv / val.csv / test.csv
    │
    ▼
preprocessing.py
    ├── clean_text()            # lowercase, remove punctuation
    ├── expand_to_binary()      # 1 MCQ row → 4 binary samples
    ├── CountVectorizer (OHE)   # 10,000 features, binary=True
    ├── TfidfVectorizer         # 10,000 features, ngram (1,2)
    ├── cosine_similarity()     # 3 scalar features per sample
    └── sparse hstack           # X_train_full shape: (~280k, 10003)
    │
    ├──► model_a_train.py
    │       ├── Logistic Regression     (supervised)
    │       ├── LinearSVC calibrated    (supervised)
    │       ├── Naive Bayes             (supervised, OHE only)
    │       ├── Random Forest           (supervised, 50k dense rows)
    │       ├── TruncatedSVD → KMeans   (unsupervised)
    │       ├── TruncatedSVD → GMM      (unsupervised)
    │       ├── LabelPropagation        (semi-supervised, 10% labelled)
    │       └── VotingClassifier        (ensemble: LR + SVM, soft vote)
    │
    ├──► model_b_train.py
    │       ├── distractor_vectorizer   (CountVectorizer on articles only)
    │       ├── distractor_ranker       (LogisticRegression, 3 features)
    │       └── hint_scorer             (LogisticRegression, 5 features)
    │
    ▼
model_evaluate.py ─────────────────► models/eval_results.json
    │
    ▼
ui/app.py  (streamlit run ui/app.py)
    ├── Screen 1 — Article Input
    ├── Screen 2 — Quiz
    ├── Screen 3 — Hints
    └── Screen 4 — Analytics Dashboard
```

## Dataset

**Source:** [RACE Dataset — Kaggle](https://www.kaggle.com/datasets/ankitdhiman7/race-dataset)

>  The three Kaggle files (train.csv, val.csv, test.csv) are **identical**. Download any one, rename it `source.csv`, place it at `data/raw/source.csv`, and run `create_splits.py` to generate real splits.

### Raw Schema

| Column | Type | Description |
|--------|------|-------------|
| id | str | Unique row identifier |
| article | str | Full reading passage |
| question | str | MCQ question |
| A | str | Option A text |
| B | str | Option B text |
| C | str | Option C text |
| D | str | Option D text |
| answer | str | Correct label: one of A / B / C / D |

### Split Sizes (after 80/10/10 stratified split, `random_state=42`)

| Split | File | Rows | Expanded Rows |
|-------|------|------|---------------|
| Train | data/raw/train.csv | ~70,000 | ~280,000 |
| Validation | data/raw/val.csv | ~8,750 | ~35,000 |
| Test | data/raw/test.csv | ~8,750 | ~35,000 |

Splits are stratified on `answer`. Zero overlap verified by `id` assertion in `create_splits.py`.

## Model Details

### Binary Expansion

Each MCQ row is expanded into 4 binary classification samples — one per option. The correct option gets label=1, the other three get label=0. This creates a 3:1 class imbalance (75% negative, 25% positive) which is handled with `class_weight='balanced'` on all classifiers.

### Feature Matrix

| Feature Group | Dimensions | Notes |
|---------------|------------|-------|
| OHE (CountVectorizer binary) | 10,000 | `min_df=2`, `max_df=0.95`, article doubled for weight |
| Cosine: article ↔ question | 1 | Batch-computed, stays sparse |
| Cosine: article ↔ option | 1 | |
| Cosine: question ↔ option | 1 | |
| **Total (X_full)** | **10,003** | Stored as scipy sparse CSR matrix |

### Model A — Supervised

| Model | Key Params | Notes |
|-------|-----------|-------|
| Logistic Regression | C=1.0, class_weight=balanced, max_iter=1000 | Best single model |
| LinearSVC (calibrated) | C=1.0, class_weight=balanced, CalibratedClassifierCV(cv=3) | Calibrated for predict_proba |
| Naive Bayes | alpha=1.0 | Uses X_ohe only (non-negative required) |
| Random Forest | n_estimators=100, class_weight=balanced | First 50k rows dense — documented limitation |
| Ensemble | VotingClassifier(LR + SVM, voting=soft) | |

### Model A — Unsupervised

| Model | Key Params | Notes |
|-------|-----------|-------|
| TruncatedSVD | n_components=100 | Applied before all clustering |
| KMeans | k=2, n_init=10 | |
| GaussianMixture | n_components=2, max_iter=200 | |
| LabelPropagation | kernel=knn, n_neighbors=7, 10% labelled | Semi-supervised |

### Model B — Distractor Generation

1. Article split into sentences via regex on `.!?`
2. Sentences ranked by cosine similarity to correct answer
3. Filter: remove sentences containing correct answer text (first 30 chars)
4. Diversity penalty: `score = base_sim − 0.5 × sum(sim to already selected)`
5. LR ranker re-orders candidates using 3 features: `sim_to_article`, `sim_to_correct`, `len_ratio`
6. Top-3 selected

### Model B — Hint Generation

1. Article split into sentences
2. Each sentence scored by cosine similarity to the question
3. LR scorer (5 features: sim_to_question, sim_to_article, length, position, word_overlap)
4. Ranked low → high relevance
5. Hint 1 = least relevant, Hint 2 = median, Hint 3 = most relevant
6. Sentences containing the correct answer text are filtered out

## UI Screens

### Screen 1 — Article Input
- Paste any English reading passage manually
- Or click **Load Random RACE Sample** to load a real RACE question with ground truth
- Submit saves article, question, options, and correct answer to session state

### Screen 2 — Quiz
- Question displayed with four A/B/C/D radio buttons
- **Check Answer** runs `predict_answer()` via Model A ensemble
- Green `st.success` if correct, red `st.error` if wrong
- Model confidence shown as a percentage metric
- All attempts logged to session history

### Screen 3 — Hints
- Three buttons: Hint 1 (General) → Hint 2 (Specific) → Hint 3 (Near Answer)
- Each button is disabled until the previous hint is revealed — skipping is not possible
- **Reveal Answer** button only appears after all three hints are viewed
- Generated distractors can also be shown for inspection

### Screen 4 — Analytics Dashboard
- All test-set metrics displayed as `st.metric` tiles
- Confusion matrix as interactive Plotly heatmap
- KMeans / LabelPropagation unsupervised scores
- BERT/T5 benchmark comparison table
- Session log table with CSV download

## Constraints

- **No neural networks** — PyTorch, TensorFlow, transformers, BERT, T5 are all prohibited
- `evaluate` library (HuggingFace) is allowed — it is a metric library, not a model
- Allowed: scikit-learn, pandas, numpy, scipy, joblib, gensim, nltk, plotly, streamlit
- All sparse matrices must stay sparse — never call `.toarray()` on full dataset
- `fit_transform()` only on training data; `transform()` on val and test
- `random_state=42` everywhere
- `class_weight='balanced'` on all classifiers

---

## Known Limitations

- **Distractors are full sentences** — extracted from the article rather than concise MCQ-style phrases. This causes near-zero BLEU/ROUGE vs the short reference options in RACE.
- **No syntactic form matching** — distractors are not forced to match the grammatical form of the correct answer (e.g., noun phrase vs full clause).
- **RF memory constraint** — Random Forest trained on only 50,000 rows due to sparse→dense conversion overhead.
- **Ensemble regression** — the 2-model soft-vote ensemble underperforms LR alone because LR and LinearSVC produce correlated errors on the same TF-IDF features.
- **Exact Match ceiling** — 33% Exact Match is 8 points above random chance (25%) but well below neural baselines. The fundamental limitation is that bag-of-words features cannot capture cross-sentence reasoning.
- **Low KMeans silhouette (0.055)** — correct vs incorrect options are not geometrically separable in TF-IDF space because both draw vocabulary from the same article.
